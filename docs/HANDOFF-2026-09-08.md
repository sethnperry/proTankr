## 2. Security & data-integrity audit (passes 1–3)

Live authorization pen-test using an anon JWT + the demo-login route to act as
a real user under real RLS; structural introspection (pg_policies, pg_proc,
grants) handed to the operator as SQL.

**Findings fixed:**
- **SECURITY DEFINER functions** `upsert_driver_profile`,
  `admin_get_carded`, `admin_remove_terminal_access` verified the *caller* was
  an admin but never that the *target* user belonged to that company — an admin
  of any company could write arbitrary users' profile PII / terminal access.
  Fixed: target-membership check added + `search_path` pinned.
  (`20260907150000_secdef_target_membership_checks.sql`)
- **`get_display_names_full` / `get_display_names`** could enumerate names/PII
  across companies — hardened to the caller's company.
- **RLS gaps:** `load_lines` had a global-read hole; `dispatcher_notes` had a
  NULL-company edge; `user_companies` allowed self-delete of membership and had
  no uniqueness constraint. All fixed.
- **`/api/admin/setup`** must scope the target to the caller's own company (R5).
- **`/api/demo/start`** gated to non-production (`VERCEL_ENV`).
- **`begin_load` / `couple_combo` / `claim_combo`** authorization verified/fixed;
  planned-load cancellation made atomic + server-enforced
  (`cancel_planned_load`, replaces a client read-then-delete TOCTOU).
- **`uuid = text` operator bugs** in policies fixed (decouple_events truck/trailer
  ids are `text`, not `uuid`).

**Planner math validation:** 15 safety tests; the core invariant — the
weight-constrained plan (`solveMaxGallons`) never exceeds the payload ceiling —
proven. No defects.

Consolidated audit write-ups: `docs/audit-pass1-db-authorization.md`,

## 3. Load-flow bug fixes (device checklist)

All build-clean and confirmed by the operator on a real device.

| Bug | Cause | Fix |
|---|---|---|
| Rotating the phone mid-plan wiped the plan / "backed out to planner" | `ShellChrome` rendered `{children}` at different tree depths per orientation → React remounted the whole page on rotate, resetting all page state | Stable wrapper shape across orientations so the subtree is preserved (`CalculatorLayoutClient.tsx`) |
| Offline LOAD showed raw "TypeError: Failed to fetch" | native fetch error surfaced in `alert()` | `friendlyLoadError()` humanizes network failures; complete-load errors now show in the modal's own themed banner, modal stays open for retry (`useLoadWorkflow.ts`, `page.tsx`) |
| Reopen mid-load → empty compartments / wrong terminal | app *deliberately* discards an in-progress plan on fresh mount | `activePlannedLoad` localStorage marker (written at begin, cleared at complete/cancel): reopen resumes the plan + its terminal; a completed load still doesn't resurrect (`utils/activePlannedLoad.ts`, `usePlanSlots.ts`, `useLocation.ts`) |
| Switching terminals mid-review → "No filled compartments" dead-end | products differ at the new terminal | clear "None of your planned products are sold at {terminal}" message instead |
| Empty compartments on any reload | a too-eager compPlan-hydration guard treated the terminal resolving after the combo as a "terminal switch" and skipped loading the saved plan | only mark a combo hydrated once a real key is read (`page.tsx`) |
| Any terminal switch wiped the live plan | a leftover **terminal-scoped** `compPlanKey` cleared `compPlan` on terminal change, contradicting the combo-scoped design | hydrate compPlan only on combo change, never a terminal-only change |

## 4. Plan Review "trust the number" redesign

**Problem the operator raised:** the capacity number ("you can load X") was a
black box — a driver couldn't see *why* it was safe, so they didn't trust it.

**What shipped:**
- **"Load basis · tap to tune" panel** inside Plan Review, one row per product:
  `code · temp (confidence color) · API · lb/gal · date`. Replaces the separate
  Confirm Temp step (one screen instead of two).
- **Tap a row → numeric overlay (Temp + API)** → recomputes planned gallons
  **live** and writes the submission inputs so the logged weight matches. Wiring
  is additive and reuses verified density math (`backCorrectApiTo60` +
  `lbsPerGallonAtTemp`).
- **Cap-to-block-overload:** tapping a compartment's gallons now sets that
  compartment's **cap** (feeds the weight-bounded solver) instead of a raw
  gallons override — it can no longer plan the load over target. Doubles as
  mistype recovery.
- **Confidence-colored API basis** — new pure, tested resolver
  `utils/apiBasis.ts` decides which API the density stands on and how much to
  trust it, shared by BOTH the density calc and the panel display so they can't
  disagree:
  - green = tuned / reading ≤6h · white = reading ≤7d · amber = terminal
    observed minimum · red = product published minimum.
  - **Safety:** a stale/unknown reading falls back to the **heaviest** minimum,
    so it can only make the plan more conservative, never lighter (proven by
    tests). This retired the interrupting Good/Better/Best stale overlay (code
    left dormant).
- **Popups pinned to the top** so the on-screen keyboard stops covering them.

**Tests:** `npm test` → 60 passing (native node runner, no deps/DB/browser),
including new `apiBasis` tier/heaviest-minimum tests and tune-density-direction
tests (a denser reading always yields fewer gallons, never more).

## 5. Verification methodology & caveats (READ THIS)

- **The audit passes were live-pen-tested** (anon JWT + demo login under real
  RLS; structural checks via SQL run by the operator).
- **The load-flow / Plan Review work was NOT live-testable from the AI session**
  — no browser and no service-role DB access here. It was verified by: `npx tsc
  --noEmit` clean, `npx next build` clean, `npm test` (60 pure tests) clean, and
  **the operator confirming each change on a real device** across iterations.
- Safety-critical density/solver math is covered by pure unit tests precisely
  because live testing wasn't available.
- No migration was required for §3–§4 (all app code + already-existing columns).
